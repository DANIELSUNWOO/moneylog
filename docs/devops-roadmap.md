## 0. 왜 교안 범위를 넘어서는가

교안(1-10)의 목표는 **"배포해봤다"**이다. 우리 목표는 한 단계 위인 **"배포를 운영해봤다"**이다.
지향하는 직무가 인프라·클라우드 엔지니어라,
"동작한다"보다 **"왜 그렇게 구성했고, 무엇을 포기했는가"**를 설명할 수 있는 쪽이 값어치가 크다.

다만 **비용과 시간은 유한하다.** 그래서 교과서적 정답이 아니라 **트레이드오프를 명시한 선택**을 한다.

## 1. 단계별 계획

### Step 1 — 컨테이너화 (교안 2장)
- `backend/Dockerfile` — 멀티스테이지(JDK 빌드 → JRE 실행), non-root 실행
- `frontend/Dockerfile` — 이미 작성됨(node 빌드 → nginx)
- `.dockerignore`로 빌드 컨텍스트 축소
- **검증**: 로컬에서 이미지 빌드 후 단독 실행

### Step 2 — 로컬 3컨테이너 통합 (교안 3장 + 우리 구조)
- `docker-compose.yml`(공통·운영) + `docker-compose.override.yml`(로컬 빌드)
- mysql + backend + frontend, healthcheck로 기동 순서 제어
- **여기서 프론트 빌드 문제를 전부 잡는다.** EC2로 넘어갈 때 새 변수는 인프라뿐이도록.
- **검증**: `docker compose up -d --build` 후 http://localhost 에서 전 기능 동작

### Step 3 — CI (교안 4장)
- `.github/workflows/ci.yml` — backend/frontend를 `paths` 필터로 분리
- 백엔드는 H2 테스트 프로파일로 `./gradlew build`, 프론트는 `npm ci && npm run build`
- **검증**: PR에 초록 체크

### Step 4 — AWS 기반 준비 (Layer 1)
- 비용 알람(Budgets $5) + 프리티어 알림 — **리소스 생성 전에 먼저**
- 루트 계정 MFA, 작업용 IAM 사용자 분리
- VPC·보안그룹 설계: **80/443/22만 개방, 3306과 8080은 열지 않는다**
  (프론트 nginx가 80에서 받아 `/api`를 백엔드 컨테이너로 프록시하므로 8080 노출이 불필요)
- EC2(t3.micro) + 스왑 2GB + Docker 설치

### Step 5 — CD (교안 6장 + 개선)
- GHCR에 이미지 push, 태그는 **`:latest` + `:{git-sha}` 둘 다**
  → sha 태그가 있어야 **롤백할 대상**이 생긴다
- EC2 재배포
- **검증**: main 머지 → 자동 배포 → 실접속 URL 동작

### Step 6 — Layer 1 운영 기본기
| 항목 | 내용 |
|------|------|
| HTTPS | 도메인 + Let's Encrypt(certbot) 또는 ACM. `http://IP`와 `https://도메인`은 신뢰도가 다르다 |
| 배포 인증 개선 | SSH 키 대신 **OIDC + SSM Session Manager** → 22번 포트를 아예 닫고, 만료되지 않는 키를 GitHub에서 제거 |
| 롤백 절차 | sha 태그로 되돌리는 명령을 문서화하고 **실제로 한 번 해본다** |
| 로그·모니터링 | CloudWatch Agent로 컨테이너 로그 수집 + 알람 |
| 백업 | DB 볼륨 백업 스크립트 + **복구 리허설**(백업이 있다가 아니라 복구해봤다가 핵심) |

### Step 7 — Terraform (Layer 2, 차별화)
- VPC/서브넷/보안그룹/EC2를 코드로 정의
- **"인프라를 지우고 그대로 재생성할 수 있다"**를 증명 — 클라우드 엔지니어 채용에서 가장 직접적인 신호

### Step 8 — (여유 시) k3s
- EKS는 컨트롤플레인만 월 $72라 크레딧을 태운다. **k3s를 EC2에 설치**하면 사실상 0원으로 같은 개념(Deployment/Service/Ingress/롤링 업데이트)을 경험할 수 있다
- 교안 1-11의 K8s 산출물을 비용 없이 확보하는 경로

## 2. 교안과 다르게 가는 지점

| # | 교안 | 우리 | 근거 |
|---|------|------|------|
| 1 | 컨테이너 2개(app+db) | **3개(frontend+backend+db)** | 프론트를 React로 분리했다 |
| 2 | 8080을 0.0.0.0/0 개방 | **80만 개방, 8080 비공개** | nginx가 `/api`를 프록시하므로 백엔드를 인터넷에 노출할 이유가 없다. 여는 포트가 줄면 공격면이 준다 |
| 3 | compose 파일을 로컬용·운영용 두 벌 | **base + override** | 두 벌은 한쪽만 고치는 사고가 난다. override는 로컬에서 자동 병합되고 EC2에선 무시된다 |
| 4 | 이미지 태그 `:latest`만 | **`:latest` + `:{sha}`** | latest만으로는 롤백 대상이 없다 |
| 5 | Java 17 | **Java 21** | 로컬 환경과 일치, LTS |
| 6 | 운영 `ddl-auto: update` | **환경변수로 `validate` 전환 가능** | update는 운영 데이터가 걸린 순간 위험하다 |
| 7 | 이미지에 프로파일 하드코딩 | **환경변수로 주입** | 같은 이미지를 다른 환경에서 쓸 수 있어야 한다(12-factor) |
| 8 | SSH 키를 Secrets에 저장 | **OIDC + SSM으로 대체(Step 6)** | 만료되지 않는 자격증명 + 22번 포트 개방을 없앤다 |

## 3. 비용 원칙

- **NAT Gateway를 쓰지 않는다** (월 ~$32). 교과서적 "DB는 프라이빗 서브넷" 설계는 우리 규모에서 비용이 효용을 넘는다.
  대신 **DB 컨테이너의 포트를 아예 노출하지 않는 것**으로 같은 목적을 달성한다.
- **ALB를 쓰지 않는다** (월 ~$16). 단일 인스턴스에서는 nginx가 그 역할을 한다.
- **EKS 대신 k3s**. 컨트롤플레인 비용 $72/월을 0으로.
- 이 선택들을 **회고에 근거와 함께 남긴다.** 비용과 아키텍처의 트레이드오프 판단이 곧 역량이다.
